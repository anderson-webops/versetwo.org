# Screen redesign proposal — October 22, 2026

Proposal branch: `claude/versetwo-redesign-ux-da75d5`. Not merged, tagged or released. Suggestion 1 (one page per activity) was added on the same branch at Jacob's request; see below.

Jacob asked for a total redesign that improves usability, readability and flow. The October 20 copy rules still apply: this redesign changes layout, navigation and typography only. It adds no taglines, introductions, takeaways or interface commentary. Every visible word comes from existing content, except the navigation labels "Practice" (home section heading) and "Previous" / "Next" (page sequence).

## Problems found in v0.1.2

1. **Home was a single list.** It showed only the ten artist names. The seven activities, the main entry the brief calls for, were two clicks away.
2. **Contents lists were walls of underlined links.** Stories and Practice opened with ten and seven wrapping inline links. They had no numbers, skill or time, and disappeared once you scrolled.
3. **Long pages had no wayfinding.** Practice is a long single page. Once you scrolled past the top links, there was no way to see where you were or jump to another activity.
4. **No forward path.** The intended sequence (Start → Stories → Practice → Your week → Next step) existed only in the header. Pages ended without a next step.
5. **Heavy blocks and weak grouping.** Examples were white-on-black slabs, articles were separated only by rules, and Your week stacked Music and Learning text with no structure.
6. **Oversized headings and a tall header.** The 5.2rem h1 and 100px header pushed content below the fold, especially on phones.
7. **Light theme only.** It had no dark theme, although the stylesheet already declared `color-scheme`.

## What changed

| Area | Change |
|---|---|
| Frame | Full-width header and footer bands with a centred 1120px column. Pill navigation with a solid current-page state. The header is sticky from 760px wide (static on phones to save height). Anchors are offset so the header never covers them. |
| Type | System UI stack at 17–18px with 1.7 line-height, a 66-character measure and smaller headings (h1 max 3.25rem). Verses use a serif (Charter / Iowan / Georgia). |
| Home | Two card grids: **Artist stories** (number, name, skill · year) and **Practice** (number, title, skill · minutes). Activity metadata is parsed from each activity's existing eyebrow. |
| Stories / Practice | A numbered contents list (activities include their minutes). From 1000px it becomes a sticky sidebar beside the content. On narrower screens it is a compact tile grid. Each story or activity is a separate panel. |
| Activities | Examples sit in a soft tinted panel with a label instead of a black slab. Step markers are coloured (native list semantics kept). Disclosures have a header strip when open. Source cards use a responsive grid. |
| Your week | Each day is a card. From 760px, Music and Learning sit side by side under small uppercase labels. |
| Next step | Support routes are cards in an auto-fitting grid. The suggested questions are tinted speech blocks. |
| Flow | Previous / Next links at the end of the five main pages follow the header order. |
| Themes | A dark palette follows `prefers-color-scheme`. All text pairs measure at least 5.0:1 in both themes, and focus rings at least 3:1. `check_static.py` now checks these values. |
| Motion | Hover transitions apply only under `prefers-reduced-motion: no-preference`. |

### Print is untouched

The old stylesheet's print-relevant rules (base rules plus `@media print`, in cascade order) moved into a single `@media print` block. The new design lives only in `@media screen`. `print.html` is byte-identical. The WeasyPrint 70.0 packet render is text-identical and pixel-identical (60 dpi, all 16 pages) to the v0.1.2 baseline. The checked-in PDFs therefore needed no regeneration.

## Generator changes

- `build_prototype.py` builds the home cards, contents lists and pager from `profile_data` and the activity HTML. It no longer uses hand-written card markup. The practice page no longer appends activity 07 through the shared `page()` replacement path.
- `artist_learning_increment.py` now supplies `NEW_CARD_META` (labels only) instead of card HTML.
- `check_static.py` adds the screen palette contrast in both themes, print/screen separation, contents lists on Stories and Practice, links from home to every activity, and pager links across the main flow.

## One page per activity

Practice was about seven phone screens long. Each activity now has its own page, `practice-<id>.html` (flat files, so relative links and offline opening work as before):

- `practice.html` is a card list of the seven activities (title, skill and minutes). Each card keeps the old fragment as its `id`, so earlier `practice.html#show`-style links and bookmarks still land on the right activity.
- On an activity page, the activity title is the page `h1`, and the inner headings move up one level. From 1000px, a sticky sidebar lists all seven activities and highlights the current one. On narrower screens the sidebar is hidden, so the activity starts right away. The header marks Practice as the current section (`aria-current="true"`).
- Previous / Next links run Practice → 01 … 07 → Your week.
- Story buttons, Your week links and home cards point directly to the activity pages. The print packet keeps its original `practice.html#id` targets, so `print.html` and both PDFs are unchanged.
- Publication allowlist: `build_site.py` and the independent `verify_site.py` list all seven pages (20 public files). New regression tests check that every generated site file is published, that the builder and the verifier agree, and that a missing activity page fails the build. `check_static.py` checks one article per activity page, the legacy anchors, and the activity pager sequence.

The navigation pills still wrap to two rows below about 400px. A scrolling single row would hide "Next step", so wrapping is kept.

### Glanceable-information audit

The redesign was checked against the glanceable-information guidance (Cowan's 3–5 chunks, NN/g scanning depth, dashboard search cost and the NIST ballot study) behind Jacob's card rules:

- **Cards:** these were already within the rules, so nothing changed. Every card has one identity anchor and two supporting facts: story cards show skill and year, and activity cards show skill and minutes. Each card is a single link. Activity panels have at most one primary and one secondary action.
- **Overview on activity pages:** the NIST ballot study found that one-at-a-time screens without a view of the rest caused confusion. At phone width the activity sidebar used to be hidden, which left each activity page isolated. Phones now get a compact 01–07 strip with the current activity marked; full names stay in each link's accessible name. Wide screens keep the full sidebar.
- **Grouping:** the home page listed ten artist cards as one group, above the suggested 4–7 per labeled group on phones. They are now two labeled groups of five: "Writing and words" (Black Thought, GZA, Little Simz, Eminem, Lupe Fiasco) and "Sound and preparation" (Rapsody, Megan Thee Stallion, Erykah Badu / J Dilla, Rakim, Doechii). The groups are taken from each story's existing skill label. Story numbers stay as cross-references to the Stories page; the Stories page order and the print packet are unchanged.
- **Depth:** the home page's Practice section now starts within the first two screenfuls at 375px (1,167px) and above the fold on desktop (684px).
